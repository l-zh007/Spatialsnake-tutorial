Module 1: Cell-Cell Communication (CellPhoneDB)
=================================================

``CellPhoneDB`` infers directed ligand-receptor interactions between annotated
cell populations. The Spatialsnake module accepts annotated ``.h5ad`` and
SpatialData ``.zarr`` objects. It supports permutation-based statistical
inference, optional spatial microenvironment restrictions, and DEG- or
transcription-factor-informed prioritization.

CellPhoneDB evaluates communication at the cell-type or spot-type level. For
spatial data, a microenvironment restricts candidate cell-type pairs to types
that co-occur within a specified region. It does not itself model spot-to-spot
distance or direct physical contact.

Input and command
-----------------

``sample.txt`` contains the sample ID and the annotated object path:

.. code-block:: text

   sample_id   input_path
   Colon_Cancer_P2_008um   results/Colon_Cancer_P2_008um/annotation/Colon_Cancer_P2_008um.zarr

Run the module with:

.. code-block:: bash

   spatialsnake single_analysis sample.txt visium \
     --option=advance_analysis --runpipe=cellPhoneDB \
     --configfile advance_analysis.yaml --threads 8

Before running the module, ensure that ``celltype_col`` identifies a valid
annotation column in ``adata.obs``. The default column is ``celltype``.

1. Statistical analysis without spatial restriction
----------------------------------------------------

This is the basic CellPhoneDB workflow. The statistical method permutes cell
type labels to identify ligand-receptor interactions that are specific to an
annotated cell-type pair. Use this setting when a global communication summary
is required, or when no defensible spatial-region prior is available.

To explicitly run without a spatial restriction, leave both microenvironment
sources empty. Setting ``niche_col`` to an empty string prevents the workflow
from using an existing ``spatial_cluster`` column.

.. code-block:: yaml

   species: "human"
   cellPhoneDB_input: ""
   cpdb_method: "statistical"
   counts_data: "hgnc_symbol"
   threshold: 0.1
   pvalue: 0.05
   iterations: 1000
   output_name: ""
   celltype_col: "celltype"
   is_single_cell: false
   niche_col: ""
   microenvs_file_path: ""
   degs_file_path: ""
   active_tf_path: ""

``threshold`` specifies the minimum fraction of cells or spots expressing each
interaction partner. ``pvalue`` defines the significance threshold used for
the statistical results. ``iterations`` controls the number of label
permutations; 1,000 iterations is the recommended default for routine
analysis. When ``output_name`` is empty, the sample ID is used as the result
suffix.

For a single-cell input, set ``is_single_cell: true``. This disables automatic
use of spatial niches but retains the same CellPhoneDB statistical workflow.

2. Spatially restricted analysis using ``niche_col`` or a file
---------------------------------------------------------------

For spatial data, CellPhoneDB can restrict the tested cell-type pairs to types
that share a microenvironment. This is useful when tissue domains, manually
defined regions, or prior spatial annotations indicate that some cell types do
not plausibly co-occur.

The default setting is:

.. code-block:: yaml

   is_single_cell: false
   niche_col: "spatial_cluster"
   microenvs_file_path: ""

If ``adata.obs["spatial_cluster"]`` exists, Spatialsnake generates
``{sample}_microenvs.txt`` from the unique ``celltype_col``--``spatial_cluster``
combinations and uses it for CellPhoneDB. This is the preferred route when
``spatial_cluster`` was generated by CellCharter, BANKSY, or a curated spatial
annotation workflow.

Alternatively, provide a two-column file:

.. code-block:: text

   cell_type    microenvironment
   NK_cells     location_1
   T_cells      location_1
   Myeloid      location_2

.. code-block:: yaml

   niche_col: ""
   microenvs_file_path: "results/Colon_Cancer_P2_008um/cellphonedb_microenvironments.txt"

The first column must match the cell-type labels in ``celltype_col`` exactly.
A cell type may be assigned to more than one microenvironment. The workflow
first uses a valid ``niche_col`` and only falls back to
``microenvs_file_path`` when that column is absent. Therefore, set
``niche_col: ""`` when an external file should take precedence over an existing
``spatial_cluster`` column.

If neither the requested niche column nor a valid microenvironment file is
available, the workflow records the decision in the log and runs without a
spatial restriction. This behaviour avoids failure for standard annotated
spatial objects while keeping the applied analysis mode explicit.

3. DEG- and active-TF-informed analysis
----------------------------------------

CellPhoneDB DEG mode is appropriate when the biological question is defined by
a precomputed differential-expression contrast. It identifies interactions for
which all interaction partners pass the expression threshold and at least one
cell type--gene pair occurs in the supplied DEG table. DEG mode does not use
the permutation p-value table; it reports relevant interactions instead.

.. code-block:: yaml

   cpdb_method: "degs"
   degs_file_path: "results/DEG_list.txt"
   active_tf_path: "results/active_TFs.txt"
   threshold: 0.1
   niche_col: "spatial_cluster"
   microenvs_file_path: ""

The DEG file must contain the cell type in its first column and the associated
gene in its second column. Additional columns are ignored. The cell-type labels
must match ``celltype_col`` exactly. ``degs_file_path`` is required when
``cpdb_method: "degs"``.

``active_tf_path`` is optional in both statistical and DEG modes. Its first
column contains the cell type and its second column contains an active
transcription factor. When supplied, the file is passed to CellPhoneDB CellSign
to prioritize interactions supported by downstream receptor-to-TF activity.
The same ``niche_col`` and ``microenvs_file_path`` logic described above applies
to DEG mode.

Mouse data
----------

The CellPhoneDB interaction database is human-centred. For
``species: "mouse"``, Spatialsnake downloads the MGI one-to-one protein-coding
orthology table, converts mouse gene symbols to human HGNC symbols, and applies
the same conversion to optional DEG and active-TF files. The resulting analysis
is a human-ortholog-projected CellPhoneDB analysis. Unmapped and non-one-to-one
genes are excluded.

Visualization and interpretation
--------------------------------

The workflow automatically produces a compact set of complementary figures:

* ``{sample}_heatmap.png`` summarises the number of significant or relevant
  interactions for each cell-type pair.
* ``{sample}_dot_plot.png`` displays the highest-ranked interactions for a
  selected directed cell pair.
* ``{sample}_dot_family_plot.png`` focuses on a selected or automatically
  prioritized signaling pathway or gene family.
* ``{sample}_chord_plot.png`` displays up to eight top-ranked interactions and
  is skipped when a valid chord diagram cannot be formed.
* ``{sample}_gene_expression.png`` summarises expression of selected
  ligand-receptor genes across cell types. Dot colour encodes cell-type-scaled
  mean expression and dot size encodes the fraction of expressing cells or
  spots.
* ``{sample}_selected_interactions.csv`` records the ligand-receptor rows used
  in the dot, focused, and chord visualizations, including the selected sender,
  receiver, ranking, interaction score, mean expression, and p-value or
  relevant-interaction flag.
* ``{sample}_microenvironment.png`` is generated only when a microenvironment
  restriction is used and shows cell type--microenvironment membership.

Without manual plot filters, the workflow selects the directed cell pair with
the largest number of significant or relevant interactions. It then ranks
interactions by CellPhoneDB interaction score, mean expression, and p-value,
displaying up to 20 interactions in dot plots and up to eight in the chord
plot. The focused plot uses the most represented significant CellPhoneDB
classification when no pathway or gene-family filter is supplied.

The automatic selection can be overridden in ``advance_analysis.yaml``:

.. code-block:: yaml

   cell_pairs: ""          # multiple pairs, e.g. Tumor_II|Tumor_I,Tumor_II<->T_cell
   cell_type1: ""          # sender cell type
   cell_type2: ""          # receiver cell type
   gene_family: ""         # chemokines, th1, th2, th17, treg, costimulatory, or coinhibitory
   cpdb_pathway: ""        # CellPhoneDB classification/pathway
   interaction_pairs: ""   # comma-separated ligand-receptor pairs
   cpdb_genes: ""          # comma-separated genes for the expression plot

``cell_pairs`` has priority over ``cell_type1`` and ``cell_type2``. It accepts
directed pairs written as ``A|B`` or ``A->B``. Bidirectional requests can be
written as ``A<->B`` and are expanded into both ``A|B`` and ``B|A``. When
multiple pairs are supplied, Spatialsnake writes one set of pair-specific
figures for each pair, using filenames such as
``{sample}_Tumor_II_to_Tumor_I_dot_plot.png``. The first selected pair also
keeps the legacy filenames, such as ``{sample}_dot_plot.png``.

``interaction_pairs`` filters the ligand-receptor pairs shown inside each
selected cell pair. Otherwise, ``cpdb_pathway`` and ``gene_family`` define the
focused interaction plot. Empty fields retain automatic selection from
significant results. CellPhoneDB interactions are directional: ``A|B`` and
``B|A`` should be interpreted separately because the ligand/receptor partners
are evaluated in opposite cell types.

Output files
------------

.. code-block:: text

   results/{sample}/cellPhoneDB_results/
   ├── adata.h5ad
   ├── {sample}_cellid_cell_type.txt
   ├── {sample}_microenvs.txt                 # only when a microenvironment is used
   ├── {sample}_heatmap.png
   ├── {sample}_dot_plot.png                  # skipped when no significant/relevant interaction is available
   ├── {sample}_dot_family_plot.png            # skipped when no focused interaction is available
   ├── {sample}_chord_plot.png                 # skipped when no valid chord can be formed
   ├── {sample}_gene_expression.png            # skipped when no selected genes are available
   ├── {sample}_selected_interactions.csv
   ├── {sample}_{sender}_to_{receiver}_dot_plot.png          # generated for multi-pair visualization
   ├── {sample}_{sender}_to_{receiver}_dot_family_plot.png   # generated for multi-pair visualization
   ├── {sample}_{sender}_to_{receiver}_chord_plot.png        # generated for multi-pair visualization
   ├── {sample}_{sender}_to_{receiver}_gene_expression.png   # generated for multi-pair visualization
   ├── {sample}_microenvironment.png           # only when a microenvironment is used
   └── cellphonedb_output/
       ├── statistical_analysis_means_{output_name}.txt
       ├── statistical_analysis_pvalues_{output_name}.txt
       ├── statistical_analysis_significant_means_{output_name}.txt
       ├── statistical_analysis_interaction_scores_{output_name}.txt
       └── statistical_analysis_deconvoluted_{output_name}.txt

In DEG mode, ``degs_analysis_relevant_interactions_{output_name}.txt`` replaces
the statistical p-value table. Review the heatmap first to identify prominent
cell-type pairs, then inspect the dot and focused plots to evaluate individual
ligand-receptor candidates in their biological and spatial context.



Minimal example
---------------

We use the reannotated object at ``results/Colon_Cancer_P2_008um/reannotation/Tumor/Tumor.zarr`` to demonstrate CellPhoneDB analysis.
``sample.txt`` should contain at least the sample ID and input object path:

.. code-block:: text

   samples path_to_dir
   Colon_Cancer_P2_008um results/Colon_Cancer_P2_008um/reannotation/Tumor/Tumor.zarr

Recommended parameters are described in :doc:`../config_reference/advance_analysis_yaml`.

.. code-block:: yaml

   cellPhoneDB_input: ""
   cpdb_method: "statistical"
   counts_data: "hgnc_symbol"
   output_name: "Colon_Cancer_P2"
   threshold: 0.1
   threads: 16
   pvalue: 0.05
   iterations: 1000
   microenvs_file_path: ""
   active_tf_path: ""
   degs_file_path: ""
   niche_col: "spatial_cluster"
   is_single_cell: False
   celltype_col: "celltype"
   cell_pairs: "Tumor_I<->Tumor_II"
   cell_type1: "Tumor_II"
   cell_type2: "Tumor_I"
   gene_family: ""

Run the workflow
~~~~~~~~~~~~~~~~

.. code-block:: bash

   spatialsnake single_analysis sample.txt visium --option=advance_analysis --runpipe=cellPhoneDB  --threads 8 --output_name Colon_Cancer_P2

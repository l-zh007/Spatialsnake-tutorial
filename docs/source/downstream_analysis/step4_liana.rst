Module 3: Cell-Cell Communication (LIANA)
==========================================

``liana`` uses LIANA to provide a unified framework for ligand-receptor inference across multiple scoring methods and resources.
In Spatialsnake, this module is intended as a flexible complementary analysis to CellPhoneDB and CellChat: users can switch methods, change the ligand-receptor resource, and focus the visualization on selected sender cells, receiver cells, or ligand-receptor pairs.

LIANA does not impose an explicit spatial-distance or microenvironment constraint in this workflow.
For spatial transcriptomics data, the spatial scope should therefore be controlled by the input object itself.
For example, users may run LIANA on a whole annotated sample, on a region-of-interest subset, or on a reannotation/reclustering subset generated by ``spatialsnake useful_tool --option=splitting``.
This design keeps the communication model simple while allowing the biological question to define the analysis range.

For the complete parameter reference, see :doc:`../config_reference/advance_analysis_yaml`.


Analysis workflow
----------------------------------------------------------------------------------

The LIANA workflow performs the following steps:

1. Read a SpatialData ``.zarr`` object or an AnnData ``.h5ad`` object.
2. Use ``celltype_col`` to define sender and receiver cell populations.
3. Run the selected LIANA method with the selected ligand-receptor resource.
4. Export the complete result table and a ranked top-interaction table.
5. Apply optional user-defined source, target, and ligand-receptor pair filters for plotting.
6. Generate compact dot plot, tile plot, source-target heatmap, ligand-receptor gene-expression summary, and, when supported by the result structure, circle plot summaries.
7. Save the result object with LIANA results stored in ``.uns``.

The input object must contain at least two valid cell populations in ``celltype_col``.
If the selected column is missing or contains only one valid group, the module stops with a clear error because sender-receiver communication cannot be defined.


Input sample file
----------------------------------------------------------------------------------

Prepare a ``sample.txt`` file with the sample ID and input object path.
For single-cell data, use the corresponding ``.h5ad`` path.

.. code-block:: text

   sample_id input_path
   Colon_Cancer_P2_008um results/Colon_Cancer_P2_008um/reannotation/Tumor/Tumor.zarr

The example above runs LIANA on a tumor reannotation subset.
If the subset contains ``Tumor_I``, ``Tumor_II``, ``Tumor_III``, and ``Tumor_IV``, LIANA will infer communication among these tumor subtypes only.


Basic configuration
----------------------------------------------------------------------------------

The default configuration performs a global LIANA analysis and automatically selects the strongest interactions for visualization.

.. code-block:: yaml

   runpipe: "liana"
   celltype_col: "celltype"
   liana_method: "cellphonedb"
   liana_resource_name: "consensus"
   liana_expr_prop: 0.1
   liana_min_cells: 5
   liana_use_raw: true
   liana_pvalue: 0.05
   liana_top_n: 6
   liana_source_celltypes: ""
   liana_target_celltypes: ""
   liana_cell_pairs: ""
   liana_pairs: ""

The most important parameters are:

.. list-table::
   :header-rows: 1
   :widths: 28 24 48

   * - Parameter
     - Typical value
     - Description
   * - ``celltype_col``
     - ``celltype``
     - Observation column used to define sender and receiver populations.
   * - ``liana_method``
     - ``cellphonedb`` / ``rank_aggregate`` / ``cellchat``
     - Communication scoring method. ``cellphonedb`` is a practical default; ``rank_aggregate`` is useful for consensus-style ranking.
   * - ``liana_resource_name``
     - ``consensus``
     - Ligand-receptor resource used by LIANA.
   * - ``liana_expr_prop``
     - ``0.1``
     - Minimum expression proportion used to remove sparse ligand-receptor signals.
   * - ``liana_min_cells``
     - ``5``
     - Minimum cells required per group.
   * - ``liana_pvalue``
     - ``0.05``
     - Significance cutoff used for p-value-based plotting methods.
   * - ``liana_top_n``
     - ``6``
     - Number of top interactions shown in the focused plots.
   * - ``liana_source_celltypes``
     - ``Tumor_I,Tumor_II``
     - Optional comma-separated sender cell types used only for focused plotting.
   * - ``liana_target_celltypes``
     - ``Tumor_II,Tumor_III``
     - Optional comma-separated receiver cell types used only for focused plotting.
   * - ``liana_cell_pairs``
     - ``Tumor_I|Tumor_II,Tumor_III<->Tumor_I``
     - Optional exact directed or bidirectional cell-pair filter. This has priority over source/target set filters.
   * - ``liana_pairs``
     - ``TGFB1|TGFBR2,CXCL12|CXCR4``
     - Optional comma-separated ligand-receptor pairs used only for focused plotting.


Running LIANA
----------------------------------------------------------------------------------

Run the module with:

.. code-block:: bash

   spatialsnake single_analysis sample.txt visium --option=advance_analysis --runpipe=liana

For Visium HD or cell-segmentation-derived objects:

.. code-block:: bash

   spatialsnake single_analysis sample.txt visium_HD --option=advance_analysis --runpipe=liana


Focused visualization examples
----------------------------------------------------------------------------------

To visualize communication among ``Tumor_I``, ``Tumor_II``, and ``Tumor_III`` only, set both sender and receiver filters:

.. code-block:: yaml

   celltype_col: "celltype"
   liana_source_celltypes: "Tumor_I,Tumor_II,Tumor_III"
   liana_target_celltypes: "Tumor_I,Tumor_II,Tumor_III"
   liana_cell_pairs: ""
   liana_pairs: ""

This keeps the complete LIANA result table available, but ``dotplot.png``, ``tileplot.png``, ``communication_heatmap.png``, ``gene_expression.png``, and ``liana_plot_data.csv`` are restricted to interactions among the selected tumor subtypes.
If no interaction matches the user-defined filters, the workflow records a warning and falls back to automatically selected top interactions so that the module still produces interpretable summary plots.

To inspect exact directed cell pairs without expanding to all source-target combinations:

.. code-block:: yaml

   celltype_col: "celltype"
   liana_cell_pairs: "Tumor_I|Tumor_II,Tumor_III|Tumor_I"

Use ``A|B`` or ``A->B`` for a directed sender-to-receiver pair.
Use ``A<->B`` to request both directions.
When ``liana_cell_pairs`` is set, it takes priority over ``liana_source_celltypes`` and ``liana_target_celltypes``.

To focus on specific ligand-receptor pairs:

.. code-block:: yaml

   celltype_col: "celltype"
   liana_source_celltypes: "Tumor_I,Tumor_II,Tumor_III"
   liana_target_celltypes: "Tumor_I,Tumor_II,Tumor_III"
   liana_cell_pairs: ""
   liana_pairs: "TGFB1|TGFBR2,CXCL12|CXCR4"

The pair syntax is ``ligand|receptor``.
Multiple pairs are separated by commas.

To switch the method while keeping the same resource:

.. code-block:: yaml

   liana_method: "rank_aggregate"
   liana_resource_name: "consensus"

For rank-based methods, smaller rank values are prioritized.
For p-value-based methods, lower p-values are prioritized and interaction strength is used as the secondary ordering criterion.
For score-based methods, higher scores are prioritized.


Supported ``liana_method`` values
----------------------------------------------------------------------------------

The workflow validates the following method names against the installed LIANA interface:

1. ``cellphonedb``: CPDB-style mean-expression and p-value based scoring.
2. ``connectome``: Network-strength-oriented ligand-receptor scoring.
3. ``natmi``: Specificity-weighted ligand-receptor scoring.
4. ``singlecellsignalr``: LRscore-based prioritization.
5. ``cellchat``: Probability-based scoring analogous to CellChat.
6. ``geometric_mean``: Geometric-mean-based aggregation.
7. ``logfc``: Fold-change-oriented ligand-receptor prioritization.
8. ``rank_aggregate``: Consensus ranking across multiple methods.
9. ``scseqcomm``: Alternative interaction scoring in the LIANA framework.

The aliases ``log2fc`` and ``cellphone_db`` are automatically mapped to ``logfc`` and ``cellphonedb``, respectively.


Output files
----------------------------------------------------------------------------------

The output directory is:

.. code-block:: text

   results/
   └── {sample_id}/
       └── liana_output/
           ├── {sample_id}.zarr
           ├── liana_results.csv
           ├── liana_top_interactions.csv
           ├── liana_plot_data.csv
           ├── liana_pair_summary.csv
           ├── dotplot.png
           ├── tileplot.png
           ├── communication_heatmap.png
           ├── gene_expression.png
           └── circle.png

``liana_results.csv``
   Complete LIANA result table returned by the selected method.

``liana_top_interactions.csv``
   Ranked high-priority interactions after method-aware sorting.

``liana_plot_data.csv``
   Exact interaction table used for ``dotplot.png`` and ``tileplot.png`` after optional source, target, and pair filtering.

``liana_pair_summary.csv``
   Source-target summary table containing the number of interactions, significant interaction count when available, mean score, and best score.

``dotplot.png``
   Focused ligand-receptor dot plot. Color represents the selected interaction-strength score, and dot size represents the selected specificity or significance score.

``tileplot.png``
   Compact ligand/receptor statistic plot. When LIANA returns ligand and receptor expression statistics, fill represents mean expression and labels represent expression proportion, following the official LIANA tileplot interpretation.

``communication_heatmap.png``
   Stable source-target overview. For p-value-based methods, the heatmap summarizes significant interaction counts; otherwise it uses an interaction summary score.

``gene_expression.png``
   Dot plot of the ligand and receptor genes selected for visualization. Color shows scaled mean expression per gene, and dot size shows the expressing-cell fraction.

``circle.png``
   Global cell-type communication network. This plot is generated only when LIANA's plotting backend can construct a stable network from the current result table; otherwise it is skipped without interrupting the workflow.

The result ``.zarr`` stores the LIANA table in ``.uns`` so that advanced users can reload the object and perform additional custom filtering or visualization.
